## Контрольные вопросы
### 1. В чем разница между UIKit и SwiftUI?
UIKit — это классический императивный объектно-ориентированный фреймворк, где разработчик вручную создает экземпляры представлений (UIView/UIViewController), настраивает их свойства, управляет жизненным циклом и явно обновляет UI при изменении данных. SwiftUI — современный декларативный фреймворк, в котором интерфейс описывается как чистая функция от состояния (State). При изменении данных SwiftUI автоматически вычисляет разницу (diffing) и производит минимально необходимую перерисовку элементов. SwiftUI написан на Swift с использованием Result Builders, легковесных структур и обеспечивает сквозную поддержку всех платформ Apple.

### 2. Как устроен жизненный цикл View в SwiftUI?
В отличие от UIKit, где UIView живет долго в памяти, структуры View в SwiftUI являются легковесными, временными и пересоздаются всякий раз при изменении наблюдаемого состояния. Жизненный цикл View управляется средой выполнения SwiftUI и включает три ключевые фазы: 1) Создание экземпляра структуры и вычисление свойства body; 2) Сравнение нового графа представлений с предыдущим деревом рендеринга (diffing); 3) Вызов модификаторов жизненного цикла: onAppear (когда элемент становится видимым на экране), task (асинхронная задача при появлении с автоматической отменой) и onDisappear (при скрытии элемента с экрана).

### 3. Какова роль контейнеров HStack, VStack и ZStack?
Это фундаментальные примитивы компоновки SwiftUI: VStack (Vertical Stack) выстраивает дочерние элементы вертикально один под другим; HStack (Horizontal Stack) размещает элементы горизонтально слева направо (с учетом RTL-локализации); ZStack (Depth Stack) накладывает элементы друг на друга по оси глубины Z. Каждый стек принимает параметры alignment (выравнивание) и spacing (расстояние между элементами), а внутри себя распределяет доступное от родителя пространство согласно приоритетам макета (layoutPriority) и гибкости дочерних View.

### 4. Что такое модификаторы интерфейса и почему строгий порядок их применения критически важен для конечного результата?
Модификаторы в SwiftUI — это методы, которые не изменяют существующий объект View «на месте», а оборачивают его в новый тип-обертку (ModifiedContent<CurrentView, Modifier>). Из-за этого порядок их применения строго определяет иерархию слоев. Например, вызов .padding().background(Color.blue) сначала добавляет внешние отступы вокруг текста, а затем окрашивает всю увеличенную область в синий цвет. Если вызвать их в обратном порядке: .background(Color.blue).padding(), сначала будет окрашена только граница текста, а затем вокруг синего прямоугольника добавятся прозрачные поля.

### 5. Как работает механизм навигации с использованием NavigationStack, NavigationLink и navigationDestination(for:destination:)?
NavigationStack обеспечивает программное управление стеком экранов. Он может быть привязан к коллекции NavigationPath или массиву значений Hashable через Binding ($path). Элемент NavigationLink(value: someData) регистрирует нажатие и помещает типизированное значение в стек навигации без прямого создания целевого экрана. Модификатор .navigationDestination(for: DataType.self) { value in ... } связывает тип данных с фабрикой соответствующего представления. Это разделяет объявление точки перехода и логику сборки экрана, предотвращая утечки памяти и упреждающее создание неактивных представлений.

### 6. В чем разница между обертками свойств @State и @Binding? В каких случаях используется каждая из них?
@State является источником истины (Source of Truth) для локального изменяемого состояния конкретного View; SwiftUI аллоцирует для него постоянное хранилище вне жизненного цикла самой структуры View. @Binding — это двухсторонняя ссылка (ссылочный мост) к значению, которым владеет родительское представление (@State родителя или свойство модели). @Binding используется в дочерних переиспользуемых компонентах (например, TextField, Toggle, CustomPicker), чтобы они могли читать и модифицировать значение, не владея им.

### 7. Зачем нужен и как применяется макрос @Observable для отслеживания внешних изменений?
Макрос @Observable (появившийся в Swift 5.9 и iOS 17 в рамках фреймворка Observation) заменяет устаревший протокол ObservableObject и обёртки @Published/@ObservedObject. Макрос анализирует поля класса на этапе компиляции и встраивает код регистрации доступа. SwiftUI отслеживает только те конкретные свойства объекта, к которым реально обращается body конкретного View. Если изменяется свойство, не используемое данным экраном, повторного рендеринга не происходит. Это устраняет оверхед производительности и делает код лаконичным.

### 8. Что такое SafeArea?
SafeArea (безопасная область) — это область экрана, гарантированно свободная от перекрытия аппаратными и системными элементами: вырезом Dynamic Island / «чёлкой», закруглениями углов дисплея, строкой состояния (Status Bar) и нижней полосой жестов Home Indicator. По умолчанию SwiftUI размещает контент внутри SafeArea. Для фоновых подложек, градиентов или полноэкранных камер используется модификатор .ignoresSafeArea(), позволяющий растянуть декоративные слои на весь физический экран.

### 9. Как реализовать адаптивный интерфейс, который корректно отображается как на компактных экранах iPhone, так и на больших экранах iPad?
Адаптивность в SwiftUI достигается комбинацией подходов: 1) Использование относительных и гибких размеров (frame(maxWidth: .infinity)) вместо фиксированных пикселей; 2) Отслеживание системных классов размеров через @Environment(\.horizontalSizeClass) (compact для iPhone в портрете, regular для iPad и iPhone Plus в ландшафте); 3) Использование NavigationSplitView для iPad (двух- или трехколоночные интерфейсы сайдбара) с автоматическим сжатием в NavigationStack на iPhone; 4) Использование адаптивных сеток LazyVGrid(columns: [GridItem(.adaptive(minimum: 160))]).

### 10. Как передавать глобальные зависимости или данные сквозь всю иерархию экранов?
В SwiftUI для сквозной передачи зависимостей используется механизм Environment. Экземпляр зависимости внедряется в корневое представление с помощью модификатора .environment(dependencyInstance) или .environmentObject(legacy). Любое дочернее представление на любой глубине иерархии навигации может получить доступ к этой зависимости через обёртку @Environment(MyType.self) private var dependency. Это исключает необходимость ручной сквозной передачи («prop drilling») через инициализаторы десятков промежуточных View.

import Foundation

/// Формат штрихкода карты
enum BarcodeFormat: String, Codable, CaseIterable {
    case code128 = "CODE128"
    case ean13 = "EAN13"
    case qr = "QR"
}

/// Дисконтная карта покупателя
struct DiscountCard: Identifiable, Hashable {
    let id: UUID
    var name: String
    var cardNumber: String
    var barcodeFormat: BarcodeFormat
    var categoryId: String
    var colorHex: String
    var discountPercent: Int?
    var note: String
    var createdAt: Date
    
    init(id: UUID = UUID(), name: String, cardNumber: String,
         barcodeFormat: BarcodeFormat = .ean13, categoryId: String,
         colorHex: String = "#e11d48", discountPercent: Int? = 5,
         note: String = "", createdAt: Date = .now) {
        self.id = id
        self.name = name
        self.cardNumber = cardNumber
        self.barcodeFormat = barcodeFormat
        self.categoryId = categoryId
        self.colorHex = colorHex
        self.discountPercent = discountPercent
        self.note = note
        self.createdAt = createdAt
    }
}

/// Категория карты

### CardStore.swift
```swift
import Foundation
import Observation

/// Источник данных для экрана Лабораторной работы № 1
@Observable
final class CardStore {
    var cards: [DiscountCard] = []
    var selectedCategoryId: String? = nil
    var searchText: String = ""
    
    init(cards: [DiscountCard] = SampleCards.initialCards) {
        self.cards = cards
    }
    
    var filteredCards: [DiscountCard] {
        cards.filter { card in
            let matchesCategory = (selectedCategoryId == nil) || (card.categoryId == selectedCategoryId)
            let trimmed = searchText.trimmingCharacters(in: .whitespacesAndNewlines)
            if trimmed.isEmpty { return matchesCategory }
            let matchesQuery = card.name.localizedCaseInsensitiveContains(trimmed)
                || card.cardNumber.localizedCaseInsensitiveContains(trimmed)
                || card.note.localizedCaseInsensitiveContains(trimmed)
            return matchesCategory && matchesQuery
        }
        .sorted { $0.name.localizedCompare($1.name) == .orderedAscending }
    }
}
```

### CardHomeView.swift
```swift
import SwiftUI

/// Главный экран: каталог дисконтных карт, поиск и фильтрация
struct CardHomeView: View {
    @Environment(CardStore.self) private var store
    
    var body: some View {
        @Bindable var store = store
        List {
            summarySection
            categoryFilterSection
            cardsSection
        }
        .listStyle(.insetGrouped)
        .navigationTitle("Мои карты")
        .searchable(text: $store.searchText,
                    placement: .navigationBarDrawer(displayMode: .always),
                    prompt: "Поиск карты или магазина")
    }
    
    private var summarySection: some View {
        Section {
            HStack(spacing: 12) {
                StatBadge(value: store.cards.count, title: "карт в кошельке", icon: "creditcard.fill")
                StatBadge(value: Set(store.cards.map(\.categoryId)).count, title: "категорий", icon: "folder.fill")
                StatBadge(value: store.cards.compactMap(\.discountPercent).max() ?? 0, title: "% макс. скидка", icon: "percent")
            }
            .listRowInsets(EdgeInsets(top: 8, leading: 8, bottom: 8, trailing: 8))
        }
    }
    
    private var categoryFilterSection: some View {
        Section("Категории") {
            ScrollView(.horizontal, showsIndicators: false) {
                HStack(spacing: 8) {
                    CategoryPill(name: "Все", icon: "square.grid.2x2", isSelected: store.selectedCategoryId == nil) {
                        store.selectedCategoryId = nil
                    }
                    ForEach(SampleCategories.all) { category in
                        CategoryPill(name: category.name, icon: category.icon,
                                     isSelected: store.selectedCategoryId == category.id) {
                            store.selectedCategoryId = category.id
                        }
                    }
                }
                .padding(.vertical, 4)
            }
        }
    }
    
    private var cardsSection: some View {
        Section("Список карт (\(store.filteredCards.count))") {
            ForEach(store.filteredCards) { card in
                NavigationLink(value: Route.cardDetail(card.id)) {
                    CardRowView(card: card)
                }
            }
        }
    }
}
```
