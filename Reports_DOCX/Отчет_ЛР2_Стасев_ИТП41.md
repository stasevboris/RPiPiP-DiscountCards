## Контрольные вопросы
### 1. Каковы архитектурные ограничения хранилища UserDefaults? Данные каких типов и какого объема допустимо в нем хранить?
UserDefaults представляет собой легковесную обёртку над plist-файлом, хранящимся в песочнице приложения. При первом обращении весь файл целиком считывается в оперативную память. Допустимые типы: примитивы (Int, Float, Double, Bool, String), Date, Data, а также массивы (Array) и словари (Dictionary) из этих типов. Архитектурные ограничения: в UserDefaults категорически запрещено хранить большие бинарные файлы (фотографии, базы данных, кэш), так как чтение и перезапись всего plist-файла при любом изменении блокирует поток и расходует RAM. Рекомендуемый максимальный объем — не более нескольких сотен килобайт (настройки, флаги первого запуска, выбранная тема).

### 2. Что представляет собой протокол Codable/Decodable и как сопоставить ключи JSON со свойствами структуры, если их названия не совпадают?
Codable — это композиция протоколов Encodable и Decodable, предоставляющая стандартный декларативный механизм сериализации и десериализации данных в Swift. Для сопоставления несовпадающих ключей (например, snake_case в JSON и camelCase в Swift) внутри структуры объявляется приватное вложенное перечисление enum CodingKeys: String, CodingKey. В нем для каждого свойства указывается строковый ключ из JSON, например: case cardNumber = "card_number". Альтернативно у JSONDecoder можно включить стратегию decoder.keyDecodingStrategy = .convertFromSnakeCase.

### 3. В чем заключаются принципиальные различия между подходами к хранению данных в базах данных SQLite и Realm?
SQLite — это реляционная табличная СУБД на языке C, оперирующая строками, столбцами, внешними ключами и SQL-запросами. Преобразование записей в объекты приложения требует слоя ORM/маппинга. Realm — это документоориентированная объектная мобильная база данных с собственным движком хранения C++ Core. В Realm данные хранятся непосредственно в виде графа объектов без промежуточной реляционной трансляции (Zero-Copy Architecture). Realm считывает свойства объектов напрямую из файла методом отображения памяти (mmap), обеспечивая мгновенный доступ без затрат на десериализацию.

### 4. За что отвечают компоненты ModelContainer и ModelContext в фреймворке SwiftData?
ModelContainer — это центральный управляющий компонент постоянного хранилища (аналог NSPersistentContainer в Core Data), который конфигурирует схему данных (Schema), параметры файла базы (ModelConfiguration) и управляет миграциями. ModelContext — это рабочий контекст (scratchpad / блокнот изменений), отвечающий за отслеживание состояния объектов в памяти, вставку (insert), удаление (delete), выполнение запросов (fetch) и фиксацию транзакций в файл базы данных через метод save().

### 5. Как описываются связи между сущностями (один-к-одному, один-ко-многим) в SwiftData? Как работает каскадное удаление зависимых объектов?
Связи описываются с помощью макроса @Relationship(deleteRule:inverse:). Для связи «один-ко-многим» родительская сущность содержит массив дочерних объектов: @Relationship(deleteRule: .cascade, inverse: \Child.parent) var children: [Child] = []. Правило deleteRule: .cascade означает, что при удалении родительского объекта контекст SwiftData автоматически находит и удаляет все связанные дочерние записи. Другие правила: .nullify (обнуление ссылки у детей), .deny (запрет удаления родителя, пока есть дети), .noAction.

### 6. Что такое миграция схемы данных? В каких случаях она необходима и как реализуется при обновлении моделей?
Миграция схемы данных — это контролируемый процесс преобразования существующей базы данных на диске устройства пользователя в новую структуру при обновлении приложения (добавление, переименование или удаление полей, таблиц и связей). В SwiftData простые изменения (добавление опционального свойства) выполняются автоматически через легковесную миграцию (Lightweight Migration). Сложные изменения требуют явного определения этапов версий SchemaV1, SchemaV2 и создания SchemaMigrationPlan со стадиями WillMigrate и DidMigrate.

### 7. Как извлечь отфильтрованные и отсортированные данные из локальной базы прямо в SwiftUI-интерфейс с помощью обертки свойства @Query?
@Query — это декларативная обертка свойства SwiftData, предназначенная для использования внутри SwiftUI View. Она автоматически создает запрос к базе данных с указанием предиката фильтрации и правил сортировки, например: @Query(filter: #Predicate<DiscountCard> { $0.discountPercent != nil }, sort: \.name, order: .forward) private var cards: [DiscountCard]. При любых изменениях записей в ModelContext свойство @Query автоматически инвалидирует View и перерисовывает интерфейс.

### 8. Как обеспечить потокобезопасность при работе с базой данных Realm и/или SwiftData, если запись происходит в фоновом потоке, а чтение — в главном?
В SwiftData и Realm экземпляры моделей и контекстов привязаны к конкретному актору/потоку (Thread Confinement) и не могут напрямую передаваться между потоками. В SwiftData для безопасной работы в фоновом потоке используется ModelActor: создается кастомный актор с собственным фоновым ModelContext. Передавать между акторами можно только неизменяемые идентификаторы PersistentIdentifier. После сохранения данных в фоновом контексте основной контекст на MainActor автоматически подтягивает изменения через уведомления NSManagedObjectContextDidSave.

### 9. Что такое «ленивая загрузка» объектов из базы данных и как она помогает оптимизировать использование оперативной памяти устройства?
Ленивая загрузка (Faulting / Lazy Loading) — это механизм оптимизации, при котором база данных изначально загружает в память только легковесные структуры-заглушки (faults) с идентификатором объекта, не считывая его тяжелые поля и связанные связи. Реальные данные с диска считываются только в тот момент, когда приложение непосредственно обращается к конкретному свойству объекта. Это позволяет загружать списки из десятков тысяч записей за миллисекунды с минимальным расходом оперативной памяти.

### 10. Какие подходы существуют для шифрования локальных баз данных на устройстве iOS/iPadOS для защиты конфиденциальной информации пользователей?
1) Системное аппаратное шифрование Data Protection API на уровне файловой системы iOS (атрибуты NSFileProtectionComplete), использующее Secure Enclave и пароль устройства; 2) Криптографическое шифрование страниц базы данных с использованием SQLCipher (256-битный ключ AES), где каждая страница БД зашифрована на лету; 3) Встроенное полнодисковое шифрование Realm с 64-байтным ключом, хранящимся в iOS Keychain Services; 4) Шифрование отдельных конфиденциальных полей с помощью фреймворка CryptoKit перед сохранением в базу.

### BarcodeGenerator.swift
```swift
import CoreImage
import CoreImage.CIFilterBuiltins
import UIKit

/// Абстракция генератора штрихкодов (слабая связанность ViewModel и CoreImage)
protocol BarcodeGenerating {
    func makeBarcodeImage(from code: String, format: BarcodeFormat, targetSize: CGSize) -> UIImage?
}

/// Реализация генератора на CoreImage
struct CoreImageBarcodeGenerator: BarcodeGenerating {
    private let context = CIContext()
    
    func makeBarcodeImage(from code: String, format: BarcodeFormat, targetSize: CGSize) -> UIImage? {
        let clean = code.trimmingCharacters(in: .whitespacesAndNewlines)
        guard !clean.isEmpty, let data = clean.data(using: .ascii) else { return nil }
        
        let filter: CIFilter?
        switch format {
        case .code128:
            let f = CIFilter.code128BarcodeGenerator()
            f.message = data
            filter = f
        case .qr:
            let f = CIFilter.qrCodeGenerator()
            f.message = data
            f.correctionLevel = "M"
            filter = f
        case .ean13:
            let f = CIFilter.code128BarcodeGenerator()
            f.message = data
            filter = f
        }
        
        guard let output = filter?.outputImage else { return nil }
        let scaleX = targetSize.width / output.extent.width
        let scaleY = targetSize.height / output.extent.height
        let scaled = output.transformed(by: CGAffineTransform(scaleX: scaleX, y: scaleY))
        
        guard let cgImage = context.createCGImage(scaled, from: scaled.extent) else { return nil }
        return UIImage(cgImage: cgImage)
    }
}
```

### CardDetailViewModel.swift
```swift
import Foundation
import Observation
import UIKit

/// ViewModel экрана детальной информации карты
@Observable
final class CardDetailViewModel {
    private let card: DiscountCard
    private let generator: BarcodeGenerating
    
    @ObservationIgnored private var cachedBarcode: UIImage?
    var isFullScreenPresented: Bool = false
    
    init(card: DiscountCard, generator: BarcodeGenerating = CoreImageBarcodeGenerator()) {
        self.card = card
        self.generator = generator
    }
    
    var title: String { card.name }
    var cardNumber: String { card.cardNumber }
    var formattedNumber: String {
        let clean = card.cardNumber.replacingOccurrences(of: " ", with: "")
        if clean.count == 13 {
            let p1 = clean.prefix(1)
            let p2 = clean.dropFirst(1).prefix(6)
            let p3 = clean.suffix(6)
            return "\(p1) \(p2) \(p3)"
        }
        return clean
    }
    var colorHex: String { card.colorHex }
    var note: String { card.note }
    var discountText: String {
        if let d = card.discountPercent { return "\(d)%" }
        return "Бонусная"
    }
    
    var barcodeImage: UIImage? {
        if let cachedBarcode { return cachedBarcode }
        guard let img = generator.makeBarcodeImage(from: card.cardNumber,
                                                   format: card.barcodeFormat,
                                                   targetSize: CGSize(width: 480, height: 160)) else {
            return nil
        }
        cachedBarcode = img
        return img
    }
}
```

### ScannerViewModel.swift
```swift
import Foundation
import Observation

/// Состояния экрана сканирования
@Observable
final class ScannerViewModel {
    enum State: Equatable {
        case scanning
        case found(DiscountCard)
        case unknownCard(cardNumber: String)
        case foreignBarcode(String)
    }
    
    private let repository: CardRepository
    private(set) var state: State = .scanning
    private(set) var lastScannedCode: String?
    
    init(repository: CardRepository) {
        self.repository = repository
    }
    
    func handleScannedBarcode(_ raw: String) {
        let code = raw.trimmingCharacters(in: .whitespacesAndNewlines)
        lastScannedCode = code
        
        // Проверка: является ли код зарегистрированной дисконтной картой
        if let card = repository.card(byNumber: code) {
            state = .found(card)
        } else if code.hasPrefix("4810268") {
            // Пример постороннего штрихкода товара
            state = .foreignBarcode(code)
        } else {
            state = .unknownCard(cardNumber: code)
        }
    }
    
    func reset() {
        state = .scanning
        lastScannedCode = nil
    }
}
```
